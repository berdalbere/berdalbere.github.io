Agri Burkina : prédiction du rendement agricole par IA

Application web full-stack qui prédit le rendement de 5 cultures dans 8 provinces du Burkina Faso à partir de 24 ans de données météo, avec un conseiller agricole IA bilingue.

Supervision

Contexte

L'agriculture emploie plus de 80 % de la population active du Burkina Faso, mais les agriculteurs manquent d'outils pour anticiper leurs récoltes et planifier la saison.

Agri Burkina est mon projet de fin de Master en Data Analytics (Altınbaş University), réalisé sous la supervision du Doç. Dr. Abdullahi Abdu Ibrahim. Objectif : passer de données climatiques publiques à une prédiction de rendement exploitable, accessible depuis une application web.

Les données météo journalières (précipitations, températures max / min, rayonnement solaire) ont été collectées via l'API Open-Meteo Archive pour Ouagadougou, Bobo-Dioulasso, Koudougou, Ouahigouya, Banfora, Dédougou, Fada N'Gourma et Kaya.

Elles sont agrégées par province et par année (précipitations totales, températures moyennes, rayonnement moyen, jours sans pluie, jours de forte pluie > 20 mm), puis croisées avec les rendements de 5 cultures (mil, sorgho, maïs, niébé, coton) pour obtenir 960 enregistrements. Chaque province est rattachée à une zone climatique (sahélienne, nord-soudanienne, sud-soudanienne) selon sa latitude.

Transparence : la météo est réelle, mais les rendements sont simulés. Faute de rendements officiels publiés à l'échelle province × année, ils ont été générés à partir des moyennes nationales FAO / DGPER par culture, ajustés selon la pluie, la chaleur et la sécheresse de chaque année, avec un bruit aléatoire. Le projet est donc une preuve de concept.

Méthodologie

  1. 1Collecte

    Appels à l'API Open-Meteo par province. Le premier essai avec NASA POWER a échoué ; les limites de débit (erreurs 429) ont été gérées par des relances temporisées.

  2. 2Préparation

    Agrégation annuelle avec Pandas, feature engineering (jours secs, fortes pluies, zone climatique), encodage des variables catégorielles.

  3. 3Modélisation

    12 variables explicatives, découpage entraînement / test 80 / 20 (768 / 192 lignes), Random Forest (200 arbres) comparé à XGBoost.

  4. 4Mise en production

    Modèle sérialisé et servi par une API FastAPI, consommée par un front-end React, avec un chatbot LLM.

Les deux variables les plus influentes sont le type de culture (≈ 0,48 d'importance) et les précipitations totales (≈ 0,35) ; toutes les autres restent sous 0,05. La part non expliquée (26,8 %) tient surtout aux facteurs absents du modèle : sol, engrais, irrigation, maladies.

Ce que j'ai appris

  • Construire une chaîne de données complète, de la collecte par API jusqu'à la mise à disposition dans une application.
  • Gérer les aléas d'une API externe : changement de source (NASA POWER → Open-Meteo) et limites de débit.
  • Comparer des modèles sur des métriques objectives (R², MAE, RMSE) plutôt que sur l’intuition.
  • Encadrer un LLM par un prompt système métier pour obtenir des réponses courtes, utiles et dans la langue de l’utilisateur.
  • Être transparent sur les limites des données : un modèle n'est fiable que si ses données le sont.

Pistes : rendements officiels DGPER, imagerie satellite NDVI (Sentinel-2), données de sol, alertes SMS sécheresse, extension aux 45 provinces, PWA pour les zones rurales.
